# Практика 2. Вариант 21: Инструмент визуализации графа зависимостей

## Общее описание
Инструмент визуализации графа зависимостей для менеджера пакетов. 
Программа принимает конфигурационный файл в формате JSON, строго валидирует его и извлекает информацию о прямых зависимостях заданного пакета из файла pom.xml (формат Java Maven). 

Для получения данных используются только встроенные библиотеки Python (urllib, xml.etree.ElementTree). Сторонние библиотеки и менеджеры пакетов не используются.

## Реализованные этапы
- **Этап 1:** Минимальный прототип с конфигурацией. Чтение и строгая валидация JSON.
- **Этап 2:** Сбор данных. Получение прямых зависимостей (Java Maven). Поддержка локального режима тестирования.

## Настройки (Конфигурация)
Программа принимает путь к JSON-файлу через аргумент --config.
Пример файла config.json:

    {
        "package_name": "spring-petclinic",
        "repo_url": "https://raw.githubusercontent.com/spring-projects/spring-petclinic/main/pom.xml",
        "test_mode": true,
        "package_version": "2.7.0",
        "max_depth": 3
    }

### Описание параметров:
- package_name — имя анализируемого пакета (строка).
- repo_url — URL-адрес репозитория или путь к файлу тестового репозитория (строка).
- test_mode — режим работы с тестовым репозиторием (true/false). Если true, программа читает локальный файл configs/mock_pom.xml.
- package_version — версия пакета (строка).
- max_depth — максимальная глубина анализа зависимостей (целое число от 0 до 100).

## Структура проекта

    practice-2-var-21/
    ├── configs/
    │   ├── config.json        # Главный файл конфигурации
    │   └── mock_pom.xml       # Локальный XML для режима тестирования
    ├── src/
    │   ├── main.py            # Точка входа, CLI
    │   ├── config_reader.py   # Чтение и валидация JSON
    │   └── dependency_parser.py # Скачивание и парсинг pom.xml
    ├── tests/
    │   └── test_config.py     # Юнит-тесты для проверки конфигурации
    ├── README.md
    ├── run.bat                # Скрипт запуска для Windows
    └── run.sh                 # Скрипт запуска для Linux/macOS

## Запуск проекта

**Способ 1: Через Python напрямую**
    python src/main.py --config configs/config.json

**Способ 2: Через скрипты (Windows/Linux)**
    # Windows
    run.bat

    # Linux / macOS
    ./run.sh

## Запуск тестов
    python -m unittest discover tests

Ожидаемый вывод: Ran 4 tests in 0.0XXs ... OK
